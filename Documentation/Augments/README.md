# 증강 시스템 (공용 증강 1차)

## 등장 규칙
- **일반 전투 방(보스 방 제외)을 클리어할 때마다** 증강 선택 창이 열리고 게임이 일시정지된다. 카드 3장 중 1장을 고른다(마우스 클릭 또는 1·2·3 키).
- 한 런의 경로는 중간 방 3개(첫 방은 항상 전투) + 보스 방이라서, 런마다 증강은 **최대 3번** 나온다. 전투가 아닌 방과 보스 방, 스테이지 출구에서는 나오지 않는다.
- 카드 풀 = **공용 증강 + 현재 캐릭터의 전용 증강**. 지금 플레이어는 전용 증강이 없는 테스트 캐릭터(`HunterCharacter.TestHunterId = "test_hunter"`)라서 공용 증강만 나온다.
- 한 번에 같은 카드가 두 장 나오지 않는다. 카드 3장을 채울 만큼 후보가 없으면 남은 장수만 나오고, 후보가 하나도 없으면 창이 열리지 않는다.
- **효과가 충돌하는 증강도 계속 등장한다.** 현재 조합에서 효과가 없는 '꽝 카드'도 선택지에 섞이는 것이 의도다. 우직하게를 골라도 FX전사·Counting Star가 나오며, 반대로 치명타 증강을 먼저 골라도 우직하게가 나온다. 캐릭터 제한, 중복 획득 상한과 효율검술의 남은 타수 조건은 유지한다.
- 새 런을 시작하면 보유 증강, 콤보 시작 타, 지원스킬 잠금이 모두 초기화된다.

## 치명타 (새로 추가)
기존 게임에는 치명타가 없었다. 증강이 치명타를 전제로 하기 때문에 기본 치명타를 넣었다.
- `MeleeSlash.critChance = 0.1` (10%), `MeleeSlash.critMultiplier = 1.5` (×1.5). 인스펙터에서 조절할 수 있다.
- 판정은 근접 공격이 적중한 적마다 따로 한다. 치명타 숫자는 금색에 `!`가 붙는다.

## 공용 증강 8종
| 증강 | 효과 | 구현 해석 · 수치 |
|---|---|---|
| 효율검술 | 콤보의 1·2타 제거 | 고를 때마다 콤보가 2타씩 뒤에서 시작한다(6타 → 3~6타 → 5~6타). 한 번 더 고르면 남는 타수가 없을 때는 등장하지 않는다(최대 2회). |
| 알아하쇼 | 지원스킬 직접 사용 불가, 12타마다 자동 사용 | 적에게 맞은 근접 공격 12번(한 번의 베기에 여러 적이 맞아도 1타)마다 쿨타임과 상관없이 자동 발동한다. Q를 누르면 안내 메시지만 나온다. 중복 등장 불가. |
| Counting Star | 치명타 시 별똥별 (쿨 5초) | 치명타가 들어간 적 위치에 별이 떨어져 반경 2.4m 안의 적에게 32 피해를 준다(로비 강화 공격력 배율 적용). |
| 우직하게 | 치명타 0% 고정, 모든 공격 ×1.3 | 근접 공격 피해 ×1.3. FX전사 · Counting Star와 함께 등장하고 보유할 수 있다. 획득 순서와 관계없이 치명타는 0%를 유지하므로 함께 보유한 치명타 효과는 발동하지 않는다. |
| 야라라라 | 콤보 마지막 공격 시 가장 가까운 적 1명 넉백, 넉백된 적이 다른 적과 부딪히면 피해 | 콤보 마지막 베기(6타의 두 번째 베기)가 적중하면 7m 안에서 가장 가까운 적 하나가 약 4.5m 밀려난다. 밀려난 적과 부딪힌 다른 적이 26 피해를 입는다(적마다 1번). **보스**는 넉백되지 않고, 마지막 베기 피해가 ×1.5가 된다. |
| 예금 | 증강 선택 시마다 마석 +20 | 1번째로 고르면 이후 증강을 고를 때마다 +20(2·3번째 → 총 40). 2번째로 고르면 그 자리에서 +20 한 번. 3번째로 고르면 그 자리에서 +35 한 번(2번째 보상과 겹치지 않음). 마석은 런 보상에 더해져 로비에서 지급된다. |
| FX전사 헌터짱 | 치명타 피해 무작위(0.1~3배), 치명타 확률 +30% | 치명타 확률 10% → 40%. 치명타가 날 때마다 배율을 0.1~3 사이에서 새로 뽑는다. |
| 선물거래 전사 헌터짱 | 반격 피해 무작위(0.1~3.5배) | 저스트 회피 반격 배율(기본 1.5배) 대신 0.1~3.5 사이 무작위 배율을 베기마다 새로 뽑는다. |

- 따로 언급이 없는 증강은 효과가 겹치지 않아서 한 번만 등장하게 했다(`maxStacks = 1`). 효율검술만 여러 번 고를 수 있다.
- 보스 판정은 적 오브젝트나 그 부모에 이름이 `Boss`로 끝나는 컴포넌트(TrafficLightBoss, GameTetrominoBoss, RuinsStormBoss)가 붙어 있는지로 한다.

## 코드 구조
| 파일 | 역할 |
|---|---|
| `Assets/Liminal/Scripts/Augments/AugmentDefinition.cs` | 증강 정의(id, 이름, 설명, 레어도, 전용 캐릭터, 최대 중첩, 등장 조건, 획득 시 효과) |
| `Assets/Liminal/Scripts/Augments/AugmentCatalog.cs` | 공용 증강 목록, 전용 증강 등록(`Register`), 카드 뽑기(`Roll`, 레어도 가중치 `RarityWeights`) |
| `Assets/Liminal/Scripts/Augments/HunterAugments.cs` | 플레이어가 가진 증강과 실제 효과, 수치 상수 |
| `Assets/Liminal/Scripts/Augments/AugmentEffects.cs` | 별똥별, 야라라라 넉백 |
| `Assets/Liminal/Scripts/Augments/HunterCharacter.cs` | 캐릭터 id (전용 증강 매칭용) |
| `Assets/Gameplay/Scripts/IMeleeHitHooks.cs` | 근접 공격이 증강에 묻는 인터페이스(치명타, 반격 배율, 피해 배율, 적중 이벤트) |
| `LiminalRunDirector` | 전투 방 클리어 → `OfferAugments` → `SelectAugment` |
| `LiminalHud` | 증강 카드(공용/전용, 레어도 표시) |

## 앞으로 추가하는 방법
- **캐릭터 전용 증강**: 새 캐릭터 프리팹에 `HunterCharacter`를 붙이고 `characterId`를 정한다. 그다음 `AugmentCatalog.Register(new AugmentDefinition(id, 이름, 설명, characterId: "그 id", ...))`로 등록하면 공용 증강과 같은 풀에서 무작위로 나온다.
- **레어도**: `AugmentDefinition.rarity`를 정하고 `AugmentCatalog.RarityWeights`에서 등장 가중치를 조절한다(지금은 모두 일반, 가중치 1). 카드 우측 상단에 레어도가 색과 함께 표시된다.
- **새 효과**: 근접 공격과 관련된 효과는 `HunterAugments`의 `IMeleeHitHooks` 구현부에 넣고, 획득 시 한 번 적용하는 효과는 `onAcquire`로 넣는다.

## 검증
- `AC Roguelike/Liminal/Validate Augments` (Edit Mode, 씬 불필요): 카탈로그 무결성, 공용/전용 풀, 카드 뽑기 200회, 알아하쇼 중복 금지, 충돌 증강의 양방향 등장·획득 및 치명타 0% 유지, 효율검술 상한, FX전사·선물거래 배율 범위, 예금 지급액을 검사한다. 결과는 `Documentation/Augments/augment-validation.json`에 저장된다.
- `LiminalPlayValidation`: 전투 방을 클리어하면 증강 창이 열리고 일시정지되는지, 카드가 서로 다른 공용 증강 1~3장인지, 선택하면 증강이 적용되고 게임이 재개되는지, 재시작하면 초기화되는지 검사한다.
- 다른 자동 플레이 검증(테마, 보스, 미션 등)은 `LiminalRunDirector.SuppressAugmentOffers = true`로 증강 창을 건너뛴다. 무작위 증강 때문에 각 검증의 측정값이 달라지지 않게 하기 위해서다.
