# Game — 게임의 잔상

`stage_capture` 브랜치에 추가한 게임 테마 던전이다. 지뢰찾기의 칸, 테트리스 계열의 블록, 오락실 기기를 실제로 걸어 다니는 공간으로 만든다. 익숙한 게임의 모양을 알아보는 재미와, 다음 방의 풍경을 보고 싶은 마음을 함께 제공하는 것이 목표다.

문서 기준일: 2026-10-03. 아래 구성은 현재 빌더와 실행 코드 기준이다. 최종 방별 부하·이동 검증·화면 검수 결과는 별도 검증 보고서가 기준이다.

## 1. 제작 방향

- 바닥만 봐도 어떤 게임에서 가져온 규칙인지 알 수 있을 것.
- 큰 조형물은 구경거리로 쓰고, 전투 중에는 플레이어와 공격 예고를 가리지 않을 것.
- 게임 속 적을 떠올리게 하는 실루엣을 복셀 덩어리로 다시 구성할 것.
- 모든 물건을 똑같이 변형하지 않을 것. 리미널스페이스가 익숙한 사물의 뒤틀림을 중심으로 했다면, 이번 테마는 게임의 규칙과 도형을 공간과 적의 행동으로 옮긴다.
- 기존 아포칼립스·동굴처럼 큰 형태, 표면의 세부 표현, 조명, 전경과 배경을 함께 갖출 것. 단순한 색상 교체로 방을 늘리지 않을 것.

전체 바탕은 네이비·아이보리·회청색이다. 청록·보라·호박색·분홍색은 블록, 화면, 조작부를 구분하는 데 사용한다. 공격 예고가 장식 사이에서 묻히지 않도록 바닥의 밝기와 장식 밀도를 조절한다.

## 2. 한 판의 흐름

**도착방 01 → 전투방 3개 → 출구방 05**

중간 전투방은 02·03·04·06·07의 다섯 종류에서 선택한다. 방은 총 7종이며 한 판에는 5개를 지난다. 같은 테마 안에서 게임판, 블록 광장, 게임 기기 전시의 풍경이 바뀌도록 구성했다.

| 방 | 이름 | 역할 | 주요 구성 |
| --- | --- | --- | --- |
| Game_01 | 코인 너머의 전시장 | 도착·테마 소개 | 거대 휴대게임기, 게임패드 벤치, 아케이드 기기, 카트리지 문. 첫 구경거리 뒤로 이동 방향이 보이게 구성 |
| Game_02 | 열린 칸의 정원 | 지뢰찾기 전투방 | 눌린 칸은 바닥, 닫힌 칸은 벽. 좌우의 닫힌 칸 묶음 사이로 넓은 중앙 이동로 확보 |
| Game_03 | 쌓이지 않는 블록 광장 | 블록 전투방 | 중앙의 T형 블록 섬을 양쪽으로 우회. 큰 블록 조형물은 카메라 반대쪽 배경에 배치 |
| Game_04 | 끝나지 않는 오락실 | 기기 전시·전투방 | 아케이드, 핀볼, 레이싱, 경품 기기를 양쪽에 배치. 가운데는 조준과 회피에 쓸 수 있는 공간으로 유지 |
| Game_05 | 다음 게임의 문 | 마무리·출구 | 휴대게임기와 카트리지 문으로 테마를 다시 보여주고, 출구로 시선 유도 |
| Game_06 | 깃발 아래의 보드 | 지뢰찾기 변형 | 닫힌 칸 묶음의 위치와 깃발을 바꿔 다른 풍경과 우회 동선 제공 |
| Game_07 | 블록 낙하 관측소 | 블록 변형 | 중앙의 S형 블록 섬을 돌아 진행. 다음 블록 전시 구조물, 레이싱 기기와 휴대게임기로 다른 풍경 제공 |

## 3. 맵에 적용한 규칙

### 지뢰찾기 계열

- 2m 간격의 격자로 바닥과 벽의 관계를 읽게 할 것.
- 눌린 칸은 연속된 이동 바닥으로 사용할 것.
- 닫힌 칸은 실제 충돌이 있는 벽으로 사용할 것.
- 숫자와 깃발은 테마를 알려주는 표식으로 사용할 것.
- 적의 예고와 회피를 확인할 수 있도록 중앙 이동로를 확보할 것.

현재 숫자는 장식이다. 숨은 지뢰의 개수를 계산하거나 칸을 눌러 판을 해결하는 퍼즐은 구현하지 않았다. 깃발도 표시물이며 폭발 함정을 뜻하지 않는다.

### 블록 계열

- 블록이 어떤 모양으로 조합됐는지 게임 카메라에서 알아볼 수 있을 것.
- 개별 큐브 사이의 틈과 베벨을 남겨 한 덩어리의 벽처럼 보이지 않게 할 것.
- 이동을 바꾸는 낮은 블록과 구경거리용 높은 블록을 구분할 것.
- 중앙 T형·S형 블록 섬은 좌우 우회 경로를 남길 것. 모든 방을 같은 직선 통로로 만들지 않을 것.
- 중앙 교전 공간을 막는 천장 구조는 만들지 않을 것.

현재 블록은 고정 구조물이다. 낙하·회전·줄 지우기 판정은 없다. 관측소의 매달린 블록도 전시용이다.

### 오락실 계열

- 기기의 화면·조작부·좌석 등 기능을 알아보게 하는 부분이 카메라에 보일 것.
- 같은 기기를 반복할 때 종류와 간격을 섞어 전시장의 리듬을 만들 것.
- 거대 휴대게임기와 카트리지 문은 길을 기억하게 하는 표지로 사용할 것.
- 코인 모양은 바닥의 길 안내 장식으로 사용할 것. 현재 획득 아이템이 아니다.

## 4. 카메라·크기·이동 약속

방의 공통 규격은 **26 × 36.4m**다. 입구는 로컬 `(0, 0, 0)`, 출구는 `(0, 0, 36.4)`이며 두 연결점은 모두 +Z를 향한다. 방을 이어 붙이는 기존 던전 규칙을 따른다.

게임 씬의 기본 카메라는 **내려다보는 각도 55° · 가로 각도 35° · 거리 24m**다. [기존 테마의 카메라 분석](../StageConcepts/VariationPlan.md)을 근거로 다음과 같이 배치했다.

- 화면에서 멀리 보이는 동쪽에는 높은 기기, 대형 블록, 전시 벽을 배치한다.
- 플레이어와 카메라 사이에 놓이는 서쪽에는 낮은 벤치와 비교적 작은 소품을 배치한다.
- 방의 앞·중간·끝에 구경거리를 나눠 한 화면이 비지 않게 한다.
- 이동할 수 없는 장식은 전투 동선 바깥에 두고, 이동 공간 안의 장애물은 충돌체를 맞춘다.
- 플레이어 출발점, 적 생성 지점, 출구 사이에 실제로 통과할 수 있는 경로를 남긴다.

Meshy 소품은 원본 비율을 유지한 균등 스케일을 사용한다. 목표 높이에 맞춘 뒤 메시의 최하단을 바닥에 정렬한다. 카트리지 아치는 높이 6.4m 기준 외곽 폭이 약 10.7m지만, 실제 중앙 통과 폭은 **약 3.6~3.7m**다. 기둥 충돌체는 이 안쪽 경계에 맞췄다. 문 전체를 막는 단일 박스 충돌체를 쓰지 않는다.

카트리지 아치가 플레이어와 카메라 사이를 가리면, 아치에서 시선을 막는 렌더러를 잠시 숨긴다. 플레이어가 가림 구간을 벗어나면 원래 표시 상태로 돌아온다. 충돌체와 이동 판정은 그대로 유지하므로, 숨겨진 기둥을 통과할 수 있게 되는 처리는 아니다.

소품의 기본 정면은 +Z다. **레이싱 기기만 -X**를 향한다. 정면 기준이 다른 기기를 같은 회전값으로 배치하지 않는다. 바닥 조작부가 있는 컨트롤러 벤치는 위에서 보이는 형태도 함께 확인한다.

## 5. 몬스터 적용

게임 테마의 방에만 복셀 몬스터를 적용한다. 다른 테마의 몬스터 구성을 공통으로 바꾸지 않는다.

| 역할 | 현재 몬스터 | 읽히는 행동 | 공간과의 관계 |
| --- | --- | --- | --- |
| 접근·돌진 | 픽셀 아귀 | 입을 벌리고 낮아진 뒤 직선으로 돌진 | 열린 칸과 통로에서 공격 방향을 읽고 옆으로 피하게 함 |
| 원거리 압박 | 비트 파수꾼 | 조준 예고 후 방향을 나눈 연속 사격 | 넓은 칸과 광장에서 이동을 유도하며, 벽을 사이에 둔 위치 관계를 사용 |
| 근거리 압박 | 스택 수호자 | 팔을 들어 전방 범위를 내려찍음 | 큰 복셀 덩어리와 느린 동작으로 무게를 전달하고, 공격 뒤 접근 기회 제공 |

세 역할 모두 **접근 → 공격 예고 → 공격 → 회복**의 순서를 가진다. 예고의 후반에는 조준 방향을 고정한다. 플레이어가 본 방향과 실제 공격 방향이 갑자기 달라지지 않게 하기 위한 규칙이다.

지뢰찾기 방에는 돌진 역할의 비중을 높이고, 블록 방에는 큰 수호자를 섞는다. 오락실 방에는 세 역할을 함께 배치한다. 폐쇄된 칸과 기기를 우회할 수 있도록 게임 테마 방의 이동 경로를 사용한다.

## 6. 미션과 실행

- 미션: **G-06 · 멈추지 않는 게임**
- 목적지: **게임의 잔상** (`game`)
- 난이도: **보통**
- 목표: **세 전투 구역을 돌파하고 출구로 이동**
- 적 특성 안내: **복셀 군단 — 돌진·연속 사격·내려찍기**
- 추가 장갑·사망 폭발 변이는 적용하지 않는다.

게이트 미션 목록에서 선택한다. 미답사 목적지는 기존 게이트 규칙에 따라 `???`로 표시한다. 현재 구성에는 별도 보스방이 없다.

실행 씬은 `Assets/GameTheme/Scenes/StageConcept_Game.unity`다. Unity에서 이 씬을 열어 재생하거나, 로비 게이트에서 미션을 선택한다. 재생성은 **AC Roguelike → Game Theme → Build Game Dungeon**에서 실행한다.

게이트로 진입할 때도 게임 테마의 조명·안개·화면 효과·카메라 구도를 적용한다. 게임 테마의 방이 제거되면 진입 전 환경으로 복원한다. 별도 실행 씬에서만 테마가 보이고 로비 진입에서는 다른 조명이 남는 상황을 막기 위한 처리다.

## 7. 리소스와 검증

Meshy로 만든 기기 소품 8종과 직접 구성한 게임판·블록·전시 구조물을 함께 사용한다. 세부 제작 이력은 [MeshyAssets.md](MeshyAssets.md), 모델별 경계·삼각형 수·텍스처는 [meshy-assets.json](meshy-assets.json)에 기록했다.

- Meshy 원본 8종 합계: **57,366 삼각형 / 26.92MB**
- 반복 소품 5종: **1K 텍스처**
- 큰 상징물 3종: **2K 텍스처**
- 모델별 메시·재질·노멀맵: 각각 **1개**
- 타일과 블록 장식은 방 안에서 재질별 메시로 합친다.
- 반복 소품은 원본 메시와 재질을 공유한다.

위 수치는 리소스 원본의 합계다. 아래 수치는 반복 배치와 건축 구조물을 포함해 Unity **6000.3.19f1**에서 측정한 결과다. 근거는 [방·동선 검증 보고서](validation.json)이며, **7개 방 모두 통과**했다.

측정 범위는 활성화된 배경 메시와 건축 구조물이다. 플레이어와 실행 중 생성되는 적은 제외했다. 표의 렌더러 수는 드로콜이나 FPS가 아니다.

- 생성 지점·출구 등 지정된 목표 지점의 도달 가능 여부를 확인했다. 중간 방 중복, 연결점 어긋남, 방 영역 겹침 검사도 통과했다.
- 적 생성 지점 **15곳**은 역할별 실제 몸통의 반경·높이·충돌 여유 폭으로 검사했다. 벽과의 겹침과 발밑 지지면 검사를 모두 통과했다.
- 검사한 시드에서 **42개의 서로 다른 5방 경로**를 확인했다.

### 전투·게이트 검증

[몬스터 전투 검증](MonsterValidation/combat-validation.json)은 **37항목 통과, 오류 0개**다. 세 역할의 공격 전 예고, 조준 방향 고정, 옆으로 회피했을 때의 무피해, 범위 안의 실제 피격, 탄환의 벽 충돌, 일시정지, 사망 시 공격·예고·탄환 정리를 확인했다. 비트 파수꾼의 3연속 사격과 각 몬스터의 아주 작은 이동량이 누락되지 않는 것도 검증했다.

[게이트 검증](GateValidation/validation.json)은 **6개 미션 모두 통과, 오류 0개**다. 경로 생성, 미답사·답사 표시, 체력과 장갑 적용, 적 등록, 재시도, 로비 귀환을 확인했다. 게임 테마 진입 시 조명·안개·화면 효과·카메라 적용, 재시도 시 환경 중복 방지, 귀환 시 이전 환경 복원도 통과했다.

미션 선택창과 강화창은 **1280×720·1024×768**에서 검사했다. 반복 강화 시 글자 갱신, 창 겹침, 누락·잘림과 씬 참조 없이 공용 폰트가 로드되는 것도 확인했다.

[가림 처리 검증](occluder-validation.json)은 **10항목 통과, 오류 0개**다. 플레이어 앞을 막는 소품만 숨기고, 옆이나 뒤의 소품·무관한 렌더러는 유지하는 것을 확인했다. 가림 해제, 대상 소실, 기능 비활성화 시 이전 표시 상태로 복원되는 것도 검증했다.

[별도 실행 씬 통합 검증](play-validation.json)도 통과했다. 실제 캐릭터 이동으로 **걷기 약 2.33m·대시 약 3.12m**, **전투방 3개·복셀 적 9마리 생성**, 문 잠금과 해제, **5개 방 완료와 Victory 전환**을 확인했다.

각 전투방에서 최소 5게임초 동안 접근과 공격을 관찰했다. Game_03은 7.11초에 1회, Game_07은 5.54초에 1회, Game_02는 5.00초에 2회로 **세 방 모두 자연 공격을 확인**했다. 실제 방의 전투 화면도 [PlayValidation](PlayValidation)에 저장했다. 프레임이 빠를 때 작은 이동량이 버려지지 않도록 적의 최소 이동 제한을 0으로 설정했다.

이 통합 검증은 정적 경로 검사가 끝난 방 사이를 시험용 순간이동으로 전환하고, 관찰 후 테스트 피해로 적을 정리했다. 연속 수동 플레이나 난이도·밸런스 검증으로 해석하지 않는다. 공격 예고·실제 피해·회피·사망 처리는 위의 독립 몬스터 전투 검사로 따로 확인했다.

검증 메뉴는 **AC Roguelike → Game Theme → Validate and Capture All Rooms**다. 방별 전체 화면과 게임 카메라 화면 **총 14장**을 [Previews](Previews)에 저장했다. 실제 Unity URP를 사용한 격리된 편집 모드 캡처이며, 플레이어를 포함한다. 정면 방향 확인용 간이 메시 그림은 정식 게임 캡처를 대신하지 않는다.

**실제 기기별 FPS·프레임 시간은 측정하지 않았다.** 삼각형 수와 동선 검증 통과는 실행 성능 보장이 아니다. 화면 가림과 공격 예고의 식별은 게임 카메라 캡처와 플레이에서 계속 확인하고, 목표 기기에서 별도 성능 측정이 필요하다.
